# 镜像简介网页

## 目标
在浏览器里查看仓库中每个镜像的简介与镜像 README，并按关键字筛选。

## 需求
- 打开 MCP 服务器根路径（`:20080`）时，配置区下方显示「仓库镜像」列表：每个镜像默认只显示镜像名、tag 与一句话简介；完整 README 收起，点击该镜像才展开，再点收起，各镜像独立。
- 展开的 README 按 Markdown 渲染（标题、段落、列表、代码块、行内代码、粗体、表格、链接）。
- 镜像 README 中的原始 HTML 按文本显示，链接只允许 http/https，避免页面被注入脚本。
- 未登记简介的镜像也显示，简介处标明「未登记」。
- 列表上方有关键字输入框，输入时即时筛选；匹配规则与 MCP `search_images` 一致（镜像名、简介、镜像 README，大小写不敏感）。
- 每次打开或刷新页面显示仓库最新内容。
- 仓库不可访问时，列表处显示错误信息，配置区不受影响。

## 方案
- 子功能归属：[MCP 服务器](../README.md)；数据来自 [镜像简介与搜索](../image-meta/README.md) 登记的简介。
- 修改：Module `mcp-server/` 的 `GET /` 页面增加镜像列表与筛选框，列表在服务端生成，筛选在浏览器端完成。
- 取舍：README 用原生 `<details>/<summary>` 折叠，默认收起、点击展开，不用 JavaScript；理由是浏览器原生支持、零依赖内网可用，收起后列表只留名称、tag 与简介，多镜像时不再被长 README 撑乱。
- 取舍：筛选命中 README 时不自动展开；理由是保持零 JS，用户展开后即可查看命中内容。
- 取舍：放在 MCP 服务器页面，不改造 joxit UI；理由是简介数据就在 MCP 服务器，官方 UI 保持零维护。
- 取舍：与配置页同一页面，不另开页面；理由是只有一个入口、无需新增路由。
- 取舍：服务端用标准库渲染 Markdown 常用子集，不引入 Markdown 库或前端 CDN；理由是服务保持零依赖、内网可用，先转义再渲染天然防注入，渲染结果可在测试中校验。

## 不做
- 在网页上编辑或删除简介、删除镜像（删除镜像用 joxit UI）。
- 在 joxit UI 中显示简介。
- 网页访问认证。
