# 镜像简介与搜索

## 目标
上传镜像时附带简介与功能说明，让 MCP 能看懂仓库里有哪些镜像，并按关键字快速找到需要的镜像。

## 需求
- AI 通过 MCP 构建推送镜像时，先阅读项目（README、文档、代码），自行提炼简介（一句话）与功能说明，随推送一起提交；用户无需手工填写。
- MCP 列出仓库镜像时，每个镜像返回简介与功能说明；未经 MCP 上传（如直接 docker push）的镜像这两个字段为空。
- 可通过 MCP 工具按关键字查找镜像，匹配范围为镜像名、简介、功能说明。
- 简介按镜像名维护，与 tag 无关：同一镜像推送新 tag 时简介保留；再次推送若提供新简介则覆盖；容器重建或重启后简介不丢失。

## 方案
- 子功能归属：[MCP 服务器](../README.md)，复用其 `build_and_push`、`list_images` 与仓库 API 列举能力。
- 修改：Module `mcp-server/`
  - `build_and_push` 输入增加必填的简介、功能说明字段；工具说明要求 AI 先读项目内容自行提炼。
  - `list_images` 输出中每个镜像带上简介与功能说明。
  - 新增按关键字搜索镜像的 MCP 工具。
  - 新增挂载卷上的元数据文件，按镜像名保存简介与功能说明。
- 修改：根 Module 的 compose 为 mcp 服务增加元数据存储卷。
- 存储取舍：描述存在 mcp-server 侧独立元数据中，不写入 registry 与镜像 manifest；理由是不改官方 registry、推送时可更新描述、搜索不必拉取各 tag 的 manifest。
- 粒度取舍：镜像级而非 tag 级；简介回答“这个镜像是什么”，版本差异由 tag 表达。

## 不做
- 事后单独修改简介的独立工具（需要时随再次构建推送更新）。
- 给未经 MCP 上传的已有镜像补描述。
- tag 级描述。
- 把描述写入镜像 label 或 OCI annotations。
