# 镜像简介与搜索

## 目标
上传镜像后附带登记简介与功能说明，让 MCP 能看懂仓库里有哪些镜像，并按关键字快速找到需要的镜像。

## 需求
- AI 上传镜像后，阅读项目（README、文档、代码），自行提炼简介（一句话）与功能说明，通过 MCP 工具登记；用户无需手工填写。
- 登记时镜像必须已存在于仓库中，否则报错，避免镜像名写错导致简介丢失。
- MCP 列出仓库镜像时，每个镜像返回简介与功能说明；未登记的镜像这两个字段为空。
- 可通过 MCP 工具按关键字查找镜像，匹配范围为镜像名、简介、功能说明。
- 简介按镜像名维护，与 tag 无关：同一镜像上传新 tag 时简介保留；再次登记则覆盖；容器重建或重启后简介不丢失。

## 方案
- 子功能归属：[MCP 服务器](../README.md)。
- 修改：Module `mcp-server/`
  - 删除 `build_and_push` 工具。
  - 新增镜像上传 HTTP 端点：接收 `docker save` 导出的镜像文件与镜像名、tag，推入本仓库。
  - 新增登记工具：输入镜像名、简介、功能说明；工具说明写明本机构建、导出、上传的完整命令，并要求 AI 上传后阅读项目自行提炼简介。
  - `list_images`、`search_images` 不变。
- 修改：根 Module 的 compose 去掉 mcp 服务的 HOME 与 Docker socket 挂载，保留元数据存储卷。
- 存储取舍：描述存在 mcp-server 侧独立元数据中，不写入 registry 与镜像 manifest；理由是不改官方 registry、可随时更新描述、搜索不必拉取各 tag 的 manifest。
- 粒度取舍：镜像级而非 tag 级；简介回答“这个镜像是什么”，版本差异由 tag 表达。

## 不做
- tag 级描述。
- 把描述写入镜像 label 或 OCI annotations。
